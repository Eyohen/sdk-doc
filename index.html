Overview

The Coinley Vanilla SDK is a framework-agnostic JavaScript library for accepting cryptocurrency payments. It works seamlessly with vanilla JavaScript, WordPress, WooCommerce, PHP applications, and any web platform.

🌐 Multi-Chain Support

Support Ethereum, BSC, Polygon, Arbitrum, Optimism, Avalanche, and Celo

💵 Stablecoin Payments

Accept USDT, USDC, and other popular stablecoins

📱 Mobile Ready

Works with mobile wallets via deeplinks and QR codes

🔌 Easy Integration

Simple CDN setup with just a few lines of code

⚡ Quick Start

Get up and running in less than 5 minutes:

HTML 
<!DOCTYPE html>
<html>
<head>
    <title>Crypto Checkout</title>
</head>
<body>
    <h1>Buy Premium Plan - $100</h1>
    <button id="pay-button">Pay with Crypto</button>

    <!-- Load Coinley SDK -->
    <script src="https://unpkg.com/coinley-test@latest/dist/vanilla/coinley-vanilla.umd.js"></script>

    <script>
        // Initialize SDK
        const coinley = new CoinleyVanilla({
            apiKey: 'your-api-key',
            apiSecret: 'your-api-secret',
            apiUrl: 'https://hub.stablezact.com/api',
            theme: 'light'
        });

        // Handle payment
        document.getElementById('pay-button').addEventListener('click', function() {
            coinley.open({
                amount: 100.00,
                customerEmail: 'customer@example.com',
                merchantName: 'My Store',
                merchantWalletAddresses: {
                    ethereum: '0x742d35Cc6634C0532925a3b8D6Ac8d9dddCAE63b',
                    bsc: '0x742d35Cc6634C0532925a3b8D6Ac8d9dddCAE63b',
                    polygon: '0x742d35Cc6634C0532925a3b8D6Ac8d9dddCAE63b'
                }
            }, {
                onSuccess: function(paymentId, txHash) {
                    alert('Payment successful! TX: ' + txHash);
                    window.location.href = '/success';
                },
                onError: function(error) {
                    alert('Payment failed: ' + error);
                }
            });
        });
    </script>
</body>
</html>
✅ That's it! Your site is now ready to accept cryptocurrency payments.

⚙️ Configuration

SDK Initialization

JAVASCRIPT 
const coinley = new CoinleyVanilla({
    apiKey: 'your-api-key',              // Required
    apiSecret: 'your-api-secret',         // Required
    apiUrl: 'https://hub.stablezact.com/api', // Required
    theme: 'light',                       // Optional: 'light' or 'dark'
    debug: false                          // Optional: Enable logging

Payment Configuration

coinley.open({
    // Required
    amount: 100.00,

    merchantName: 'My Store',
    callbackUrl: 'https://mystore.com/webhook',
    
    // Wallet addresses per network
    merchantWalletAddresses: {
        ethereum: '0x...',
        bsc: '0x...',
        polygon: '0x...',
        arbitrum: '0x...',
        optimism: '0x...',
        avalanche: '0x...',
        celo: '0x...'

    // Defaults
    preferredNetwork: 'ethereum',
    preferredCurrency: 'USDT',
    
    // Custom data
    metadata: {
        orderId: '12345',
        productName: 'Premium Plan'
    }
}, callbacks);

🌐 Supported Networks

The SDK supports multiple blockchain networks for maximum flexibility:

Network Key Chain ID
Ethereum ethereum 0x1
BSC bsc 0x38
Polygon polygon 0x89
Arbitrum arbitrum 0xa4b1
Optimism optimism 0xa
Avalanche avalanche 0xa86a
Celo celo 0xa4ec
⚠️ Important: You must provide wallet addresses for each network you want to support. Only networks with configured wallets will be shown to users.

Using the Same Wallet Across Networks

Since EVM wallet addresses work across all EVM chains, you can use the same address:

JAVASCRIPT 
const myWallet = '0x9d961e093FFeC1577d124Cfe65233fE140E88Fc4';

merchantWalletAddresses: {
    ethereum: myWallet,
    bsc: myWallet,
    polygon: myWallet,
    arbitrum: myWallet,
    optimism: myWallet,
    avalanche: myWallet,
    celo: myWallet
}

💡 Examples

E-commerce Checkout

JAVASCRIPT 
document.getElementById('checkout-btn').addEventListener('click', function() {
    const cartTotal = 249.99;
    const userEmail = document.getElementById('email').value;
    
    coinley.open({
        amount: cartTotal,
        customerEmail: userEmail,
        merchantName: 'Tech Store',
        merchantWalletAddresses: {
            ethereum: '0x742d35Cc6634C0532925a3b8D6Ac8d9dddCAE63b',
            polygon: '0x742d35Cc6634C0532925a3b8D6Ac8d9dddCAE63b'
        },
        metadata: {
            orderId: 'ORD-' + Date.now(),
            items: ['Laptop', 'Mouse']
        }
    }, {
        onSuccess: function(paymentId, txHash) {
            // Update order status
            fetch('/api/orders/complete', {
                method: 'POST',
                headers: { 'Content-Type': 'application/json' },
                body: JSON.stringify({
                    orderId: 'ORD-' + Date.now(),
                    paymentId: paymentId,
                    txHash: txHash
                })
            }).then(() => {
                window.location.href = '/order-confirmation';
            });
        }
    });
});

WordPress Integration

PHP 
// functions.php
function enqueue_coinley_sdk() {
    wp_enqueue_script(
        'coinley-vanilla',
        'https://unpkg.com/coinley-test@latest/dist/vanilla/coinley-vanilla.umd.js',
        array(),
        '2.0.0',
        true
    );
    
    wp_localize_script('coinley-vanilla', 'coinleyConfig', array(
        'apiKey' => get_option('coinley_api_key'),
        'apiSecret' => get_option('coinley_api_secret'),
        'wallets' => array(
            'ethereum' => get_option('coinley_ethereum_wallet'),
            'polygon' => get_option('coinley_polygon_wallet')
        )
    ));
}
add_action('wp_enqueue_scripts', 'enqueue_coinley_sdk');

🔒 Security Best Practices

Never Expose API Credentials

While the SDK runs on the client-side, always load API credentials from your server-side configuration, never hardcode them in your JavaScript files.

  • ✅ Always use HTTPS for your website
  • ✅ Validate webhook signatures on your backend
  • ✅ Verify payments server-side, don't rely solely on client callbacks
  • ✅ Store API keys in environment variables
  • ✅ Use specific version numbers in production (not @latest)
